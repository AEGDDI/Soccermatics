10 Steps to Build Football Pass Clustering Visualisations in Python

A technical, step-by-step guide using La Liga 2015/16 event data to uncover team playing styles

Victoria Friss de Kereki
13 min read
·
Apr 17, 2026

In my last article, I explored what pass clustering visualisations can reveal about team playing styles, using examples from the Premier League 2015/16 season. I didn’t expect it to travel as much as it did — especially on LinkedIn, where it sparked a lot of engagement and thoughtful discussion around how teams structure space and how different styles emerge.

That response made me want to go a bit deeper. So this article is a natural continuation of that work. Instead of focusing on what the visualisations show, I’m going to walk through how they’re built, step by step, so you can create them yourself. This time, I’ll use StatsBomb event data from La Liga 2015/16, just to show how the same framework applies across different leagues and contexts.

The aim isn’t to build the most complex model possible. It’s to show how a relatively simple pipeline — combining event data, clustering, and a bit of statistical context — can produce something genuinely insightful, and a different way of looking at how teams play.

Step 1: Set Up Your Environment

We start by importing the tools we’ll need.

# Standard library
import math
import warnings
from pathlib import Path

# Data manipulation
import numpy as np
import pandas as pd

# Visualisation
import matplotlib.pyplot as plt
from mplsoccer import Pitch

# Football data
from statsbombpy import sb

# Machine learning
from sklearn.cluster import KMeans
from sklearn.preprocessing import StandardScaler

# Utilities
from tqdm import tqdm

warnings.filterwarnings("ignore", message="credentials were not supplied")

At a high level:

  • statsbombpy gives us access to free event data from StatsBomb
  • pandas and numpy handle the data wrangling and transformations
  • scikit-learn is used for clustering (K-Means) and feature scaling
  • mplsoccer provides the pitch for visualisations
  • tqdm is just there to make loops easier to track when loading data

One small but useful detail is the last line, where warnings are suppressed. When using statsbombpy without authentication, it can raise repeated credential warnings — which don’t affect functionality but clutter the output. This simply keeps things cleaner while running the notebook.

At this point, we’re just setting up the environment — no data yet, just the tools we’ll build on in the next step.

Step 2: Load Match Data

Before analysing passes, we first need to identify which matches to pull. StatsBomb structures its data by competition and season, each identified by an ID. In this case, 11 corresponds to La Liga and 27 to the 2015/16 season, so we use that combination to get all matches played in that campaign.

leagues = [(11, 27)]  # La Liga 2015/16

matches_df = pd.concat([
    sb.matches(competition_id=comp, season_id=season)
    for comp, season in leagues
], ignore_index=True)

As a quick sanity check, we can look at the number of matches:

len(matches_df)

This returns 380, which matches a full La Liga season (20 teams playing 38 matches each), so we know the data has been loaded correctly. To get a better sense of the structure, we can also inspect a snapshot of the dataset:

Each row represents a match and includes information such as the teams involved, match identifiers, date, and scoreline.

Step 3: Extract Pass Events

Now we move from match-level data to event-level data, where we can access every action in each game.

CACHE_DIR = Path("statsbomb_cache/events_15_16")
CACHE_DIR.mkdir(parents=True, exist_ok=True)

def load_events(match_id):
    cache_file = CACHE_DIR / f"{match_id}.parquet"
    if cache_file.exists():
        return pd.read_parquet(cache_file)
    events = sb.events(match_id=match_id)
    events.to_parquet(cache_file)
    return events

We start by setting up a cache. Event data is relatively heavy, so instead of downloading it every time we run the code, we store each match locally. The function checks whether the file already exists and only calls the API if it doesn’t.

all_passes = []

for match_id in tqdm(matches_df["match_id"], desc="Extracting passes"):
    events = load_events(match_id)
    passes = events[events["type"] == "Pass"].copy()
    passes["match_id"] = match_id
    all_passes.append(passes)
passes_df = pd.concat(all_passes, ignore_index=True)

We then loop through every match, load the full event data, and filter it down to passes. StatsBomb datasets include many different types of events, but for this analysis we only keep passing actions, since those are what we’ll use to build the visualisations.

After combining all matches, we can check the size of the dataset:

len(passes_df)

This returns 365,288 passes, giving us a full-season view of passing behaviour across La Liga.

Step 4: Clean and Structure the Data

At this point, we have all pass events, but they’re not yet in a format we can use for modelling.

passes = passes_df.dropna(axis=1, how="all").copy()

def extract_coords(col):
    x = pd.to_numeric(
        col.astype(str).str.strip("[]").str.split().str[0],
        errors="coerce"
    )
    y = pd.to_numeric(
        col.astype(str).str.strip("[]").str.split().str[1],
        errors="coerce"
    )
    return x, y

passes["start_x"],passes["start_y"]=extract_coords(passes["location"])
passes["end_x"],passes["end_y"]=extract_coords(passes["pass_end_location"])

The first step is to extract coordinates. In the raw data, locations are stored as list-like objects ([x, y]), so we convert them into separate numeric columns for start and end positions. This gives each pass a clear origin and destination on the pitch, which is what we’ll use for clustering.

We then remove a small number of edge cases. “Injury Clearance” events don’t really reflect typical passing behaviour, so excluding them keeps the dataset focused on meaningful actions.

passes = passes[passes["pass_outcome"] != "Injury Clearance"].copy()

Finally, we ensure all coordinates fall within the pitch boundaries. This is mostly a safety step to guard against any inconsistencies in the raw data.

for col, max_val in [
    ("start_x", 120),
    ("end_x", 120),
    ("start_y", 80),
    ("end_y", 80)
]:
    passes[col] = passes[col].clip(lower=0, upper=max_val)

At this stage, each pass is now cleanly represented by its start and end location on the pitch. This is the minimum structure required for clustering. To understand what we are now working with, we can inspect the dataset:

This shows a single pass-level view of the data, including contextual information such as team, player, match ID, and the newly created spatial features (start_x, start_y, end_x, end_y). Each row represents one pass event, forming the foundation for all subsequent feature engineering and clustering.

Step 5: Define the Clustering Framework

We now define how the clustering itself will work.

FEATURES = ["start_x", "start_y", "end_x", "end_y"]

def run_clustering(df, n_clusters=50, seed=14):
    scaler = StandardScaler()
    X = scaler.fit_transform(df[FEATURES])

    model = KMeans(n_clusters=n_clusters, random_state=seed, n_init=10)
    df = df.copy()
    df["cluster"] = model.fit_predict(X)

    return df, scaler

We start by selecting the features that represent each pass: start_x, start_y, end_x, and end_y. These four values fully define the geometry of a pass, meaning length and direction are already captured without needing extra variables.

We then standardise the data using StandardScaler(). Even though all features are coordinates, the pitch is not perfectly symmetrical (120x80), so scaling ensures that horizontal and vertical movements are treated equally when measuring similarity.

Next, we initialise the K-Means model with n_clusters=50, grouping passes into 50 types based purely on spatial similarity. The random_state=seed (set to 14) ensures reproducibility, while n_init=10 runs the algorithm 10 times and keeps the best result.

Finally, model.fit_predict(X) assigns each pass to a cluster, storing the result in a new cluster column. This gives us a labelled dataset we can now analyse at team level.

Step 6: Add Context with Z-Scores

Clusters on their own don’t tell us much. At this point, we’ve grouped passes into types, but we still don’t know what makes a team distinct. To get there, we need to understand how each team uses those clusters relative to the rest of the league.

def compute_zscores(df):
    team_cluster = (
        df.groupby(["team", "cluster"])
        .size()
        .reset_index(name="count")
    )

    team_total = df.groupby("team").size().reset_index(name="total")

    dist = team_cluster.merge(team_total, on="team")
    dist["prop"] = dist["count"] / dist["total"]

    league_avg = dist.groupby("cluster")["prop"].mean()
    league_std = dist.groupby("cluster")["prop"].std()

    dist["z"] = (
        (dist["prop"] - dist["cluster"].map(league_avg)) /
        (dist["cluster"].map(league_std) + 1e-6)
    )

    return dist

We start by counting how often each team uses each cluster (groupby(["team", "cluster"]).size()). This gives us raw frequencies, but those alone aren’t very meaningful because teams have different numbers of passes.

So next, we calculate the total number of passes per team and convert counts into proportions (dist["prop"]). This tells us how much each cluster represents within a team’s overall passing behaviour.

From there, we shift to a league-wide perspective. For each cluster, we compute the average usage across all teams (league_avg) and how much variation there is (league_std).

Finally, we calculate the z-score. This measures how far a team’s usage of a given cluster is from the league average, in standard deviation terms. A high positive value means the team relies on that pass type much more than others, while a negative value means they use it less.

This is the step that turns clustering into something interpretable. Instead of just counting passes, we’re now identifying which patterns are truly characteristic of each team.

Step 7: Select Representative Passes

Clusters can contain thousands of passes, which would make any visualisation cluttered and hard to interpret. Instead of plotting everything, we select a small set of representative examples for each cluster.

def representative_passes(df_cluster, scaler, n=30):
    X = scaler.transform(df_cluster[FEATURES])
    centroid = X.mean(axis=0)

    dist = np.linalg.norm(X - centroid, axis=1)
    df_cluster = df_cluster.copy()
    df_cluster["dist"] = dist

    return df_cluster.sort_values("dist").head(n)

We start by transforming the data using the same scaler as before (scaler.transform(df_cluster[FEATURES])). This ensures distances are measured in the same space used during clustering.

Next, we compute the centroid of the cluster (X.mean(axis=0)), which represents the “average” pass within that group.

We then calculate how far each pass is from that centroid using Euclidean distance (np.linalg.norm). This gives us a way to rank passes by how typical they are.

Finally, we sort by distance and keep the closest n passes (here, 30). Importantly, this is done within each team and cluster, so we’re selecting representative passes that reflect how that specific team uses that pattern.

In practice, this keeps the visualisations clean while still capturing the underlying structure of each pass type.

Step 8: Build the Team-Level Visualisation

Now we bring everything together for a single team.

pitch = Pitch(pitch_type="statsbomb", line_color="black")

def plot_team(ax, df, dist, scaler, team, display_name=None,
              top_n=5, show_descriptions=False):
    team_df = df[df["team"] == team]

    # --- handle z column naming ---
    z_col = "z_score" if "z_score" in dist.columns else "z"

    top_clusters = (
        dist[dist["team"] == team]
        .sort_values(z_col, ascending=False)
        .head(top_n)
        .reset_index(drop=True)
    )

    cmap = plt.colormaps["tab10"]

    # --- stable cluster-color mapping ---
    cluster_info = []
    for i, row in enumerate(top_clusters.itertuples()):
        cluster_info.append({
            "cluster": row.cluster,
            "color": cmap(i % 10),
            "idx": i + 1
        })

    # --- plot in reverse so #1 is on top ---
    for info in reversed(cluster_info):
        cluster_df = team_df[team_df["cluster"] == info["cluster"]]
        reps = representative_passes(cluster_df, scaler)

        for _, p in reps.iterrows():
            ax.arrow(
                p["start_x"], p["start_y"],
                p["end_x"] - p["start_x"],
                p["end_y"] - p["start_y"],
                head_width=1.2,
                head_length=2,
                linewidth=1.3,
                color=info["color"],
                alpha=0.4
            )

    # --- legend (original order) ---
    descriptions = [(c["idx"], c["color"]) for c in cluster_info]

    # --- title (with optional position) ---
    title = display_name if display_name is not None else team
    ax.set_title(title, pad=6, fontweight="bold")

    ax.invert_yaxis()
    ax.set_xticks([])
    ax.set_yticks([])

    y = -0.02

    if show_descriptions:
        for i, (idx, color) in enumerate(descriptions):
            ax.text(
                0.5,
                y - i * 0.06,
                f"➜ {idx}",
                transform=ax.transAxes,
                fontsize=9,
                color=color,
                ha="center",
                va="top"
            )
    else:
        x_positions = np.linspace(0.2, 0.8, len(descriptions))

        for x, (idx, color) in zip(x_positions, descriptions):
            ax.text(
                x,
                y,
                f"➜ {idx}",
                transform=ax.transAxes,
                fontsize=11,
                color=color,
                ha="center",
                va="top"
            )

We start by filtering the data to a single team (team_df = df[df["team"] == team]). From there, we identify that team’s most distinctive clusters using the z-scores computed earlier. By sorting on z and selecting the top n (head(top_n)), we focus only on the patterns that truly stand out relative to the rest of the league.

Each of these clusters is then assigned a colour using a colormap (plt.colormaps["tab10"]). This keeps the visual consistent and makes it easier to distinguish between different passing patterns.

For each selected cluster, we filter down again to just that team’s passes within the cluster, and retrieve a set of representative passes using the function from the previous step. These are then plotted as arrows on the pitch, using their start and end coordinates.

One subtle but important detail is the plotting order. Clusters are drawn in reverse (reversed(cluster_info)), so the most distinctive pattern (ranked #1 by z-score) is plotted last and therefore appears on top. Without this, key patterns would often be hidden underneath less important ones.

Finally, we clean up the visual by removing axes, setting a title, and adding a simple legend that maps colours to cluster rankings. The result is a compact view of how a team’s most characteristic passing patterns are structured across the pitch.

Step 9: Build the Full League View

We now scale the approach from a single team to the entire league.

def plot_grid(df, dist, scaler, title, n_cols=4, show_descriptions=False):

    TEAM_ORDER = [
        "Barcelona",
        "Real Madrid",
        "Atlético Madrid",
        "Villarreal",
        "Athletic Club",
        "Celta Vigo",
        "Sevilla",
        "Málaga",
        "Real Sociedad",
        "Real Betis",
        "Las Palmas",
        "Valencia",
        "Espanyol",
        "Eibar",
        "RC Deportivo La Coruña",
        "Granada",
        "Sporting Gijón",
        "Rayo Vallecano",
        "Getafe",
        "Levante UD"
    ]

    teams = [t for t in TEAM_ORDER if t in df["team"].unique()]

    n_rows = math.ceil(len(teams) / n_cols)

    fig, axes = plt.subplots(
        n_rows,
        n_cols,
        figsize=(18, 4 * n_rows),
        gridspec_kw={'hspace': 0.08, 'wspace': 0.05}
    )

    axes = axes.flatten()

    fig.suptitle(
        title,
        fontsize=16,
        fontweight="bold",
        y=0.91
    )

    for i, team in enumerate(teams):
        pitch.draw(ax=axes[i])

        plot_team(
            axes[i],
            df,
            dist,
            scaler,
            team,
            display_name=f"{i+1}. {team}",
            show_descriptions=show_descriptions
        )

    for j in range(i + 1, len(axes)):
        axes[j].axis("off")

    plt.tight_layout(rect=[0, 0.06, 1, 0.95])
    plt.show()

This function applies the same logic to every team. We define TEAM_ORDER to control how teams appear in the grid, using league position instead of alphabetical order to make comparisons easier.

We then create a grid of pitches and loop through each team, calling plot_team to generate their visual. Any unused plots are removed to keep things clean.

The result is a full league view, where each team’s passing structure can be compared side by side.

Step 10: Apply the Framework

Now we put everything together and run the full pipeline across different contexts.

10.1 All Passes

We start with the full dataset, without any filtering. This gives a high-level view of each team’s overall passing tendencies across all phases of play.

df_all, scaler = run_clustering(passes)
dist_all = compute_zscores(df_all)

plot_grid(
    df_all,
    dist_all,
    scaler,
    "Team Passing Style Clusters (All Passes) | La Liga 2015/16 | "
    "Top 5 Clusters (Z-Score vs League)"
)

The plot below shows the most distinctive passing patterns for each team.

At this level, clear structural differences emerge between possession-dominant and more direct teams. The top sides tend to concentrate their most distinctive clusters in higher and more advanced areas of the pitch, reflecting shorter, more controlled passing sequences and sustained possession in the opponent’s half.

In contrast, teams such as Eibar, Deportivo La Coruña, and Granada show a more direct profile, with several of their key clusters representing long passes originating deep in their own half and bypassing midfield zones entirely. This suggests a more transitional or counter-attacking approach, relying less on build-up and more on direct progression.

An interesting exception is Real Madrid, which predominantly shows short passing combinations in advanced areas but also features a distinct cluster of diagonal, cross-field switches, directed towards the forward-left attacking zone. This indicates a more varied and less predictable attacking structure compared to more positionally rigid teams.

10.2 Own Half Build-Up

We now narrow the focus to passes that start in a team’s own half. This isolates build-up behaviour and how teams progress the ball from deeper areas.

own_half = passes[passes["start_x"] <= 60].copy()

df_own, scaler = run_clustering(own_half)
dist_own = compute_zscores(df_own)

plot_grid(
    df_own,
    dist_own,
    scaler,
    "Team Passing Style Clusters (Own Half) | La Liga 2015/16 | "
    "Top 5 Clusters (Z-Score vs League)"
)

The plot below reflects passing patterns specifically in the build-up phase.

Here, structural differences become more pronounced. Top teams such as Barcelona, Real Madrid, and Atlético Madrid rely heavily on short, secure passing patterns in deeper areas, often circulating the ball towards the wide channels to escape pressure while maintaining control. In contrast, lower-table sides like Sporting Gijón, Getafe, and Levante adopt a more direct approach, frequently using longer passes from deep positions to bypass midfield pressure and progress the ball more quickly into advanced areas.

10.3 Defensive Third

Finally, we go even deeper and focus only on passes originating in the defensive third. This highlights how teams behave under the most constrained and high-risk conditions.

def_third = passes[passes["start_x"] <= 40].copy()

df_def, scaler = run_clustering(def_third)
dist_def = compute_zscores(df_def)

plot_grid(
    df_def,
    dist_def,
    scaler,
    "Team Passing Style Clusters (Defensive Third) | La Liga 2015/16 | "
    "Top 5 Clusters (Z-Score vs League)"
)

The plot below shows how teams build from the deepest areas of the pitch.

At this level, stylistic contrasts become even more pronounced. When restricting the analysis to the defensive third, many teams naturally shift towards a more direct approach, using longer passes to escape pressure and move the ball away from dangerous areas as quickly as possible.

However, Barcelona, Real Madrid, and Atlético Madrid still stand out for their continued reliance on short, controlled passing sequences even in these deep zones. This consistency highlights their ability to build under pressure without resorting to frequent long clearances, reinforcing their possession-based structure throughout the pitch.

It is also notable that Rayo Vallecano, despite being lower in the table, maintains a relatively controlled passing style across all three views, including this one, suggesting a more structured approach to build-up than their league position might imply. In contrast, Athletic Club, positioned towards the top of the table, shows a more direct profile in deep areas, relying more on longer progression out of defence.

Overall, this reinforces an important point: directness or possession style is not inherently linked to team success, but rather reflects stylistic identity and tactical choice.

Final Thoughts

What’s useful about this approach is how little is actually going on under the hood. There’s no complex modelling layer or heavy feature engineering — just a structured way of representing passes, grouping them by spatial similarity, and then putting that back into a team context.

The value comes from how these simple steps are combined. Clustering turns raw event data into patterns, z-scores turn those patterns into something comparable across teams, and the visualisation makes the structure immediately interpretable.

It’s not trying to be a definitive model of playing style. It’s a way of organising pass data so that differences between teams become easier to see and talk about.

And once this pipeline is in place, it becomes a flexible starting point — you can change the context, the filtering, or the grouping, and start asking slightly different questions about how teams actually play.
