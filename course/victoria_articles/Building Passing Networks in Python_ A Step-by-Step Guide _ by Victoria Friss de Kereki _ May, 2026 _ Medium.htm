Building Passing Networks in Python: A Step-by-Step Guide

How to construct, align, and visualise team passing structures using StatsBomb event data

Victoria Friss de Kereki
19 min read
·
May 22, 2026

--

Passing networks are one of the most expressive tools in football analytics. Rather than looking at individual passes in isolation, they reveal how a team is organised in possession — which players connect most frequently, where the ball tends to flow, and how the team’s shape manifests in the data. A network built from a single match gives a snapshot of structure; one built from an entire season reveals something closer to tactical identity.

In this tutorial, I build a full pipeline for constructing passing networks from scratch using event data from the 2015/16 Bundesliga season, provided by StatsBomb’s Open Data repository. This covers everything from data extraction and cleaning through to spatial alignment across matches, season-level aggregation, and a flexible plotting system — all driven by a single function call.

The focus is on the methodology, not performance evaluation.

Step 3: Loading and Cleaning the Data

Once the CSV exists, all subsequent work loads from it directly. The two coordinate columns — location and pass_end_location — are stored as stringified lists in the CSV, so they need to be parsed back into Python lists on read using ast.literal_eval.

I split this into two functions. clean_passes handles coordinate extraction and data quality; load_passes wraps the CSV read and calls it immediately.

def clean_passes(passes_df: pd.DataFrame) -> pd.DataFrame:
    """Extract coordinates, remove invalid passes, and clip to pitch bounds."""

    passes = passes_df.copy()

    def _coords(col, idx):
        return col.apply(lambda v: v[idx] if isinstance(v, (list, tuple)) else None)

    passes["start_x"] = _coords(passes["location"], 0)
    passes["start_y"] = _coords(passes["location"], 1)
    passes["end_x"]   = _coords(passes["pass_end_location"], 0)
    passes["end_y"]   = _coords(passes["pass_end_location"], 1)

    passes = passes[passes["pass_outcome"] != "Injury Clearance"].copy()

    for col, max_val in [("start_x", PITCH_X_MAX), ("end_x", PITCH_X_MAX),
                         ("start_y", PITCH_Y_MAX), ("end_y", PITCH_Y_MAX)]:
        passes[col] = passes[col].clip(lower=0, upper=max_val)

    return passes

def load_passes(path: str) -> pd.DataFrame:
    """Load passes from a saved CSV and return
    a cleaned DataFrame ready for plotting."""

    import ast

    passes_df = pd.read_csv(
        path,
        low_memory=False,
        converters={
            "location":          lambda x: ast.literal_eval(x) if pd.notna(x) else None,
            "pass_end_location": lambda x: ast.literal_eval(x) if pd.notna(x) else None,
        }
    )

    return clean_passes(passes_df)

StatsBomb encodes locations as [x, y] lists, so the inner _coords helper extracts index 0 (x) or index 1 (y) from each row. Injury clearances are excluded because they are not actual passes and would distort average positions. The clipping step handles rare edge cases where coordinates fall marginally outside the pitch rectangle due to data imprecision.

From this point on, the entire workflow starts from one line:

passes = load_passes("Datasets/passes_bundesliga_201516_statsbomb_all.csv")

Step 4: Helpers

Two small functions are used throughout the rest of the code and are worth defining upfront.

def _norm(x) -> str | None:
    """Lowercase and strip a player name for consistent matching."""
    return str(x).strip().lower() if pd.notna(x) else None

def format_nickname(name: str) -> str:
    """Capitalise each word of a name, preserving common particles."""
    if pd.isna(name):
        return name
    particles = {"de", "da", "del", "van", "von"}
    words = str(name).split()
    if all(w[0].isupper() or w.lower() in particles for w in words):
        return name
    return " ".join(w.lower() if w.lower() in particles else w.capitalize()
                    for w in words)

_norm lowercases and strips player names for consistent matching — the same player can appear slightly differently across the player and pass_recipient columns. format_nickname handles display labels: StatsBomb sometimes stores nicknames in all-lowercase, so this normalises capitalisation for plot labels while preserving particles like "de" and "van".

Step 5: Building a Match-Level Network

A passing network for a single team in a single match requires two things: knowing who started, and knowing where each starter typically operated on the ball.

5.1 Getting the starting XI

def get_starting_xi(match_id: int,
                    team: str) -> pd.DataFrame | None:
    """Return a DataFrame with columns [player, nickname] for the starting XI."""
    
    try:
        lineup = sb.lineups(match_id=match_id)[team]
    except Exception:
        return None

    df = lineup.explode("positions")

    pos = pd.json_normalize(df["positions"])

    df = pd.concat(
        [df.drop(columns="positions").reset_index(drop=True), pos],
        axis=1
    )

    df["player"] = df["player_name"].apply(_norm)
    df["nickname"] = df["player_nickname"]
    df["from"] = df["from"].fillna("0:00")

    df = df.sort_values("from")

    starters = df.head(11)[["player", "nickname"]]

    return starters if len(starters) >= MIN_STARTERS else None

StatsBomb lineup data stores each player’s position history as a list of dictionaries — one entry per role change during the match. Exploding and normalising that list gives a flat table with one row per position stint. Sorting by the from column (the time each position started) and taking the first 11 rows identifies who was on the pitch from kick-off. If all 11 starters can't be confirmed, None is returned and the match is excluded downstream.

5.2 Computing average positions

def build_match_network(match_id: int, team: str, passes: pd.DataFrame):
    """
    Build average node positions for one team in one match.
    Returns (node_pos_df, pass_df, xi_df) or None if data is insufficient.
    """
    
    df = passes[
        (passes["match_id"] == match_id) & (passes["team"] == team)
    ].copy()

    if df.empty:
        return None

    df["p"] = df["player"].apply(_norm)
    df["r"] = df["pass_recipient"].apply(_norm)

    xi = get_starting_xi(match_id, team)

    if xi is None:
        return None

    starters = xi["player"].tolist()

    locs = pd.concat([
        df[df["p"].isin(starters)][["p", "start_x", "start_y"]].rename(
            columns={"p": "player", "start_x": "x", "start_y": "y"}
        ),
        df[df["r"].isin(starters)][["r", "end_x", "end_y"]].rename(
            columns={"r": "player", "end_x": "x", "end_y": "y"}
        ),
    ])

    avg = locs.groupby("player").agg(
        x=("x", "mean"),
        y=("y", "mean")
    ).reset_index()

    return (avg, df, xi) if len(avg) >= MIN_STARTERS else None

The key idea here is that a player’s average position is estimated from all their on-ball actions — both when they pass (the pass start location) and when they receive (the pass end location). Using both gives a more stable estimate than passes made alone, particularly for players who receive a lot but contribute less in build-up.

5.3 Building the edges

def build_edges(pass_df: pd.DataFrame,
                node_pos: pd.DataFrame) -> pd.DataFrame:
    """Aggregate pass counts between node pairs and attach coordinates."""

    edges = (
        pass_df.groupby(["p", "r"])
        .size()
        .reset_index(name="weight")
        .rename(columns={"p": "slot_from", "r": "slot_to"})
    )

    edges = edges[edges["slot_from"] != edges["slot_to"]]

    edges = (edges
             .merge(node_pos.rename(columns={"player": "slot_from",
                                             "x": "x_start",
                                             "y": "y_start"}),
                    on="slot_from")
             .merge(node_pos.rename(columns={"player": "slot_to",
                                             "x": "x_end",
                                             "y": "y_end"}),
                    on="slot_to"))

    return edges

Edges are pass counts between pairs of players, with self-passes removed. Each edge is then enriched with the spatial coordinates of both endpoints, which are needed to draw the connecting lines on the pitch.

Step 6: Aligning Networks Across Matches

Building a season-level network means combining node positions from up to 34 matches. The core challenge is that each match has a different starting XI — players rotate in and out due to injury, suspension, or tactical choice. There is no stable one-to-one correspondence between nodes across matches: the node representing the left centre-back in match 1 might be a completely different player in match 17.

The solution is to stop thinking in terms of individual players and instead think in terms of positional slots — abstract roles like “left centre-back” or “right-sided midfielder” that exist independently of who fills them. Before aggregating, each match’s node layout is mapped to a shared reference layout using the Hungarian algorithm, which assigns each node to the closest node in the reference in a globally optimal way.

The reference is simply the node layout from the first match processed for that team — the 11 average positions from that game become the template that all subsequent matches are aligned to. This is an arbitrary choice: a different first match would produce a different reference and potentially different slot assignments. A more robust approach would use a manually defined positional template based on the team’s most common formation, but the first-match reference works well enough in practice and requires no manual input.

def _align_nodes(match_nodes: list[pd.DataFrame],
                 reference: pd.DataFrame) -> list[pd.DataFrame]:
    """Use the Hungarian algorithm to align each match's nodes
    to a shared reference layout."""

    aligned = []

    for nodes in match_nodes:
        if len(nodes) < len(reference):
            continue
        cost = np.linalg.norm(
            nodes[["x", "y"]].values[:, None, :] -
            reference[["x", "y"]].values[None, :, :],
            axis=2
        )
        r, c = linear_sum_assignment(cost)
        nodes = nodes.iloc[r].copy()
        nodes["slot"] = c
        aligned.append(nodes)

    return aligned

The cost matrix holds the Euclidean distance between every node in the match and every node in the reference. linear_sum_assignment finds the one-to-one assignment that minimises total distance — this is the Hungarian algorithm, which solves the classic assignment problem in polynomial time. Each node is then tagged with its assigned slot: a positional role that is consistent across all matches, regardless of which player occupied it.

This is also why MIN_STARTERS = 11 matters: the alignment requires exactly 11 nodes per match to map cleanly onto the 11-slot reference. A match where fewer starters can be identified from the lineup data would produce a mismatched cost matrix and unreliable slot assignments, so it is excluded entirely.

Step 7: Building a Season-Level Network

With alignment in place, the season aggregation brings everything together: collect match-level networks, align them, average positions by slot, then assign the most representative player to each slot.

def build_season_network(passes: pd.DataFrame, team: str, season: str):
    """
    Aggregate all match-level networks for a team into a season-level network.
    Returns (node_pos_df, edges_df) or None.
    """

    df = passes[(passes["team"] == team) & (passes["season"] == season)]
    if df.empty:
        return None

    match_ids = df["match_id"].dropna().unique()
    match_nodes, match_passes, xi_list = [], [], []

    for m in match_ids:
        res = build_match_network(m, team, passes)
        if res is None:
            continue
        nodes, match_df, xi = res
        match_nodes.append(nodes)
        match_passes.append(match_df)
        xi_list.append(xi)

    if not match_nodes:
        return None

    reference = match_nodes[0].copy()
    reference["slot"] = range(len(reference))

    aligned = _align_nodes(match_nodes, reference)

    if not aligned:
        return None

    nodes_df = pd.concat(aligned, ignore_index=True)

Once aligned, each node has a slot label — a positional role that is consistent across matches. The average coordinates per slot across all matches become the node's location in the season network:

    # Average position per slot
    node_pos = (nodes_df.groupby("slot")
                .agg(x=("x", "mean"), y=("y", "mean"))
                .reset_index())

Before assigning player labels to those slots, the nickname map is built. StatsBomb stores a player_nickname field in lineup data — a shorter or more recognisable name for each player (e.g. "Xabi Alonso" instead of "Xabier Alonso Olano"). The map is collected across all match lineups, deduplicated by player, and stored as a dictionary so it can be looked up quickly when labelling nodes:

    # Build nickname map from all lineups
    xi_all = pd.concat(xi_list, ignore_index=True)
    nickname_map = (
        xi_all.dropna(subset=["nickname"])
        .drop_duplicates("player")
        .set_index("player")["nickname"]
        .to_dict()
    )

Next, the most representative player for each slot is identified. A player-slot count matrix tracks how many times each player appeared in each slot across all matches. The Hungarian algorithm is applied again — this time to maximise total appearance count rather than minimise distance, giving a one-to-one assignment of players to slots:

    players = nodes_df["player"].unique()
    slots   = sorted(nodes_df["slot"].unique())
    matrix  = np.zeros((len(players), len(slots)))
    p_idx   = {p: i for i, p in enumerate(players)}
    s_idx   = {s: i for i, s in enumerate(slots)}

    counts = nodes_df.groupby(["player", "slot"]).size().reset_index(name="n")

    for _, row in counts.iterrows():
        matrix[p_idx[row["player"]], s_idx[row["slot"]]] = row["n"]

    r_ind, c_ind = linear_sum_assignment(-matrix)
    slot_to_player = {slots[j]: players[i] for i, j in zip(r_ind, c_ind)}

    node_pos["player"] = node_pos["slot"].map(slot_to_player)

    node_pos["label"]  = (node_pos["player"]
                          .map(nickname_map)
                          .fillna(node_pos["player"])
                          .apply(format_nickname))

Finally, season-level edges are built by mapping each pass to the passer’s and recipient’s most common slot, then aggregating across all matches:

    player_to_slot = nodes_df.groupby("player")["slot"].agg(lambda x: x.mode()[0])

    all_passes = pd.concat(match_passes, ignore_index=True)
    all_passes["slot_from"] = all_passes["p"].map(player_to_slot)
    all_passes["slot_to"]   = all_passes["r"].map(player_to_slot)

    edges = (
        all_passes.groupby(["slot_from", "slot_to"])
        .size()
        .reset_index(name="weight")
        .dropna()
    )

    edges = edges[edges["slot_from"] != edges["slot_to"]]

    edges = (edges
             .merge(node_pos, left_on="slot_from", right_on="slot")
             .merge(node_pos, left_on="slot_to", right_on="slot",
                    suffixes=("_start", "_end")))

    return node_pos, edges

Step 8: Drawing the Network

All visualisations share a single core drawing function. It takes an existing axis, a pitch object, node positions, and edges, and renders the complete network onto them.

def _draw_network(ax, pitch, node_pos: pd.DataFrame, edges: pd.DataFrame,
                  node_size: int = 240, label_size: int = 8,
                  watermark: bool = False) -> None:
    """Draw nodes and weighted edges onto an existing pitch axis."""
    pitch.draw(ax=ax)

    if edges is not None and not edges.empty:
        max_w = edges["weight"].max()
        for _, r in edges.iterrows():
            pitch.lines(
                r.x_start, r.y_start, r.x_end, r.y_end,
                lw=(r["weight"] / max_w) * 6,
                color="red",
                alpha=0.3 + (r["weight"] / max_w) * 0.6,
                ax=ax, zorder=1
            )
    pitch.scatter(node_pos.x, node_pos.y,
                  s=node_size, color="blue", edgecolor="black",
                  linewidth=1.2, ax=ax, zorder=3)
    label_col = "label" if "label" in node_pos.columns else "player"
    for _, r in node_pos.iterrows():
        ax.text(r.x, r.y, format_nickname(r[label_col]),
                ha="center", va="center",
                fontsize=label_size, fontweight="bold",
                bbox=dict(facecolor="white", alpha=0.6,
                          edgecolor="none", boxstyle="round,pad=0.2"),
                zorder=4)
    if watermark:
        ax.text(PITCH_X_MAX - 1, 75.5, WATERMARK_NAME,
                ha="right", va="bottom",
                fontsize=10, color="#888888",
                zorder=5)
        ax.text(PITCH_X_MAX - 1, 79, WATERMARK_SUBTITLE,
                ha="right", va="bottom",
                fontsize=9, color="#aaaaaa",
                zorder=5)

Edge width and opacity are both scaled relative to the maximum pass count in the network, so the most frequent passing relationship always renders at full weight (lw=6, alpha=0.9) and all others scale proportionally. This makes dominant connections immediately legible without losing the context of less frequent ones. Nodes sit above edges (zorder=3), and player labels sit above nodes (zorder=4) with a semi-transparent white background to stay readable even when overlapping edge lines.

The watermark flag controls whether the author credit is rendered inside the pitch — used for single and two-panel plots. For grid layouts it is placed at figure level instead (covered in the next step).

Step 9: Responsive Grid Layout

When displaying multiple networks at once, the layout needs to adapt to the number of plots. _make_grid handles this with three tiers:

def _make_grid(n_items: int, n_cols: int):
    """Return (fig, axes_list, node_size, label_size, title_size)
    for a responsive grid."""

    if n_items == 1:
        fig, ax = plt.subplots(1, 1, figsize=(10, 6))
        return fig, [ax], 400, 10, 16

    if n_items == 2:
        fig, axes = plt.subplots(1, 2, figsize=(14, 5))
        return fig, list(axes), 320, 13, 14

    n_rows = int(np.ceil(n_items / n_cols))

    fig, axes = plt.subplots(n_rows, n_cols, figsize=(18, 4 * n_rows))

    return fig, list(axes.flatten()), 240, 8, 12

A single network gets a larger figure with bigger nodes and labels. Two networks side by side get a medium size. Three or more switch to a compact grid with smaller elements to keep everything legible at scale. The same function produces well-proportioned output whether it is rendering a single season network or all 18 Bundesliga teams on one page.

_draw_grid loops over the results, calls _draw_network for each panel, hides unused axes, and places the watermark at figure level for grid layouts:

def _draw_grid(results: list, main_title: str, n_cols: int = 4) -> None:
    """Render a list of (subtitle, node_pos, edges) tuples in a responsive grid."""

    if not results:
        print("No valid results.")
        return

    fig, axes, node_size, label_size, title_size = _make_grid(len(results), n_cols)

    pitch = Pitch(pitch_type="statsbomb", line_color="black", linewidth=2)

    inside_watermark = len(results) <= 2

    for i, (subtitle, node_pos, edges) in enumerate(results):
        _draw_network(axes[i], pitch, node_pos, edges, node_size, label_size,
                      watermark=inside_watermark)
        if subtitle:
            axes[i].set_title(
                subtitle, fontsize=title_size,
                fontweight="bold", pad=0.95)

    for j in range(i + 1, len(axes)):
        axes[j].axis("off")

    fig.suptitle(main_title, fontsize=18, fontweight="bold", y=0.95)

    plt.subplots_adjust(left=0.03, right=0.97, top=0.93,
                        bottom=0.03, wspace=0.02, hspace=0.1)

    if not inside_watermark:
        fig.text(0.94, 0.045, WATERMARK_NAME,
                 ha="right", fontsize=11, color="#888888")
        fig.text(0.94, 0.040, WATERMARK_SUBTITLE,
                 ha="right", fontsize=9.5, color="#aaaaaa")

    plt.show()

Step 10: Putting It All Together

All of the above is exposed through a single entry point. plot_network inspects the arguments provided and routes to the right internal function.

def plot_network(
    passes: pd.DataFrame,
    team: str = None,
    season: str = None,
    match_id: int = None,
    match_level: bool = False,
    n_cols: int = 4
) -> None:
    """
    Universal entry point for all passing network plots.
    Parameters
    ----------
    passes      : Cleaned passes DataFrame (output of load_passes).
    team        : Team name. None = all teams (season view).
    season      : Season string e.g. "2015/2016".
    match_id    : If provided (and match_level=False), plots both teams 
                  for that match.
    match_level : If True with a team, plots every match for that team 
                  in a grid.
    n_cols      : Number of columns for grid layouts.
    """

    # Single match - both teams side by side
    if match_id is not None and not match_level:
        _plot_single_match(match_id, passes)
        return

    # All matches for one team
    if match_level and team is not None:
        _plot_team_matches(passes, team, season, n_cols)
        return

    # Season view - one team or all teams
    teams = [team] if team else sorted(
        passes[passes["season"] == season]["team"].dropna().unique()
    )
    results = []
    for t in teams:
        res = build_season_network(passes, t, season)
        if res is not None:
            subtitle = "" if team else t
            results.append((subtitle, *res))
    title = (f"{team} Passing Network - {season}"
             if team else f"Passing Networks by Team - {season}")
    _draw_grid(results, title, n_cols)

For the single-match view, _plot_single_match mirrors the away team's coordinates so both sides are shown attacking left-to-right — making side-by-side comparison intuitive without any manual adjustment:

def _plot_single_match(match_id: int, passes: pd.DataFrame) -> None:
    """Plot passing networks for both teams in a single match."""
    row = passes[passes["match_id"] == match_id].iloc[0]
    home, away  = row["home_team"], row["away_team"]
    score       = f"{row['home_score']}–{row['away_score']}"
    date        = pd.to_datetime(row["match_date"]).strftime("%d %b %Y")
    comp        = str(row.get("competition", "")).split(". ", 1)[-1]
    season      = row.get("season", "")
 
    fig, axes = plt.subplots(1, 2, figsize=(14, 6))
    pitch = Pitch(pitch_type="statsbomb", line_color="black", linewidth=2)
 
    for ax, team in zip(axes, [home, away]):
        res = build_match_network(match_id, team, passes)
        if res is None:
            ax.axis("off")
            continue
 
        node_pos, match_df, _ = res
        edges = build_edges(match_df, node_pos)
 
        # Mirror the away team so both attack left-to-right
        if team == away:
            node_pos = node_pos.copy()
            edges    = edges.copy()
            node_pos["x"] = PITCH_X_MAX - node_pos["x"]
            node_pos["y"] = PITCH_Y_MAX - node_pos["y"]
            for col in ("x_start", "x_end"):
                edges[col] = PITCH_X_MAX - edges[col]
            for col in ("y_start", "y_end"):
                edges[col] = PITCH_Y_MAX - edges[col]
 
        _draw_network(ax, pitch, node_pos, edges, node_size=300, label_size=8,
                      watermark=True)
        ax.set_title(team, fontsize=13, fontweight="bold")
 
    fig.suptitle(f"{home} {score} {away}", fontsize=16, fontweight="bold", y=0.98)

    plt.figtext(0.5, 0.915, f"{date}  •  {comp}  ({season})",
                ha="center", fontsize=12, color="gray")
    plt.tight_layout()
    plt.show()

And _plot_team_matches handles the per-match grid for a single team, sorting chronologically and labelling each panel with the opponent, scoreline, and date:

def _plot_team_matches(
        passes: pd.DataFrame, team: str,
        season: str, n_cols: int) -> None:

    """Plot a match-level grid for every game a team played in a season."""

    df = passes[(passes["team"] == team) & (passes["season"] == season)]

    match_ids = df.sort_values("match_date")["match_id"].dropna().unique()

    results = []

    for m in match_ids:
        res = build_match_network(m, team, passes)
        if res is None:
            continue
        node_pos, match_df, _ = res
        edges = build_edges(match_df, node_pos)
        row      = passes[passes["match_id"] == m].iloc[0]
        opponent = row["away_team"] if row["home_team"] == team else row["home_team"]
        score    = f"{row['home_score']}–{row['away_score']}"
        date     = pd.to_datetime(row["match_date"]).strftime("%d %b %Y")
        results.append((f"{opponent} ({score})\n{date}", node_pos, edges))

    row  = passes[passes["team"] == team].iloc[0]

    comp = str(row.get("competition", "")).split(". ", 1)[-1]

    _draw_grid(results, f"{team} - Match Networks  ({comp}  {season})", n_cols)

What These Networks Reveal

A passing network is fundamentally a graph — nodes are players at their average positions, edges are passing relationships weighted by frequency. When rendered on a pitch, the spatial layout reflects where each player typically operated, and edge thickness shows which passing combinations were most frequent relative to the team’s own maximum.

What you can read directly from the network: which players were central to the passing structure, how evenly passing responsibility was distributed, how high or deep the team’s shape sat on average, and whether the goalkeeper was actively involved in build-up. What you cannot read directly: absolute pass volumes, whether a style was intentional, or how the team performed.

At season level, individual match variation smooths out and a more stable picture of team structure emerges. Player positions reflect average territorial roles across all games; edge weights reflect cumulative passing tendencies. This makes it easier to distinguish habitual patterns from one-off tactical adjustments — and to compare structural identities across an entire league in a single view.

Final Thoughts

One thing I find interesting about passing networks is how much of the work is invisible in the final image. The visualisation looks simple — dots and lines on a pitch. But getting those dots and lines to mean something across 34 matches, with different line-ups every game, requires thinking carefully about alignment, slot assignment, and what you’re actually aggregating.

The networks here are descriptive. They don’t tell you who played better, which partnerships were effective, or why a shape looked the way it did. What they do is make structure visible in a way that raw data never quite manages — and that’s a useful starting point for deeper questions.
